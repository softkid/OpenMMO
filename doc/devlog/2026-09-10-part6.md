# Devlog - 2026-09-10 (part 6)

## Actually Fixing the Terrain Coverage Bug, Not Just Warning About It

Follow-up to part 5's diagnosis. With disk confirmed (50GB available), went
from "found the cause, left a warning" to actually fixing it.

**Three real changes.** `docker-compose.yml`'s `TERRAIN_REGION_MIN`/`MAX`
default is now the full documented world (`-16`/`15`, was `-2`/`1` — a
4x4-region dev patch covering ~1.5% of it). `terrain-bake.sh` now detects a
region-range change on its own: `worldgen.json` has carried
`baked_region_range` since before this fix, so comparing it against the
currently-configured range was free — no new marker needed, and it closes a
real bug found while investigating (changing `TERRAIN_REGION_MIN/MAX` and
restarting used to silently do nothing, because the script only checked
whether `worldgen.json` existed, never whether it matched). And before
starting a multi-minute bake, it now estimates disk need from the measured
24,834 bytes/tile figure (×3 safety margin for tree/grass data, +1GB pad)
and refuses cleanly if the available space looks short, rather than running
out partway through.

**Verified by actually running it**, not just `sh -n`. Built a throwaway
harness — fake `terrain-gen` and `chown` binaries on `PATH`, a scratch
`TERRAIN_DIR` — and exercised all six branches directly: fresh bake, skip on
a matching region, auto-rebake on a changed region, a real disk-short
rejection (this sandbox's `/tmp` only had ~9GB, and asking for the full
world's ~20GB estimate was correctly refused before touching the existing
`worldgen.json`), a smaller range that fit and rebaked successfully, and
both override flags (`TERRAIN_SKIP_DISK_CHECK`, `TERRAIN_FORCE_BAKE`). Every
exit code and log line matched what the script was supposed to do. This is
the most thoroughly exercised piece of code from the whole session — real
execution, not just parsing.

**What happens on redeploy:** nothing manual needed. The existing small-patch
`worldgen.json` won't match the new default range, so the next `docker
compose up` (or CI rebuild + pull) rebakes automatically, gated by the new
disk check. Bake time scales with region count now (global simulation is
still a fixed ~3 minutes; tile-writing isn't), so expect longer than before.
